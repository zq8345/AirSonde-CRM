### Q4 guard-design 死绑定 —— **SPEC 的「5」是对的；而且闸本身漏报，真实是 6**

先更正我自己：中途我曾判「基线是 8 不是 5，SPEC 笔误」——**那是错的**。SPEC 的 5 指的是**当前实测孤儿数**，8 是 guard 源码里冻结的 `BASELINE` 数组长度（"只许减不许加"的白名单），两者本来就不是同一个量。今天这几批已清掉 3 个（`email-body` / `email-caret` / `d-analyze`），于是 b9981ae 的 8 → d143e49 的 **5**，与 SPEC 相符。

**🟡 真发现：死绑定闸的两条 strip 正则失效，只抓得住一半形态。**

`scripts/guard-design.mjs:221-222` 写在模板字符串里：
```js
.replace(new RegExp(`\$\(\s*["']#${id}["']\s*\)`, "g"), "")
.replace(new RegExp(`getElementById\(\s*["']${id}["']\s*\)`, "g"), "");
```
模板字符串会先吃掉反斜杠：`` `\$` `` → `$`（正则里成了**行尾锚**）、`` `\(` `` → `(`（成了**分组符**）。⇒ 两条 strip **一次都没匹配上**，`stripped === html`。于是下一步"是否作为字符串实参出现"的检查 `(?<!#)["']id["']` 会命中该 id **自己的那次引用**：
- `getElementById("x")` 形态 → 留下裸 `"x"` → 判"有来源" → **永远不会被报成死绑定**；
- `$("#x")` 形态 → 留下的是 `"#x"`，被 `(?<!#)` 排除 → 能被报出来。

⇒ **这道闸目前只查得出 `$("#x")` 形态的死绑定**，而它设立的目的正是防"删元素没删绑定"。**宪章第 1 条的现场复现：判据只认得一种形态，就只查得出那一种。**
