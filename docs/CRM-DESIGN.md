# AirSonde-CRM 设计宪法

> approved by Joe · 2026-08-31
> 地位：本仓 UI 的最高约束。与派单口头措辞冲突时**以本文件为准**，并回报总工。
> 改本文件必须在末尾变更记录留一行（日期 + 改了什么 + 为什么）。

---

## 0. 目的（一句话）

**Joe 每天 10 分钟，机器 24 小时，产出是"正在对话的潜在买家"。**

**唯一北极星 = 回信数。** 不是线索数、不是发信数、不是打分数 ——
那些都是过程量，涨了不代表离成交更近；只有真人回信是。

⚠️ 这一条是所有取舍的裁判：**任何界面元素，说不清自己怎么帮到回信数，就不该占位置。**

---

## 1. 谁干什么

| 谁 | 干什么 |
|---|---|
| **Joe** | ① 接管回信（机器起草，他定稿发出）② 校准期批信（看几封再放手）③ 偶尔调方向（画像/关键词/国家） |
| **机器** | **其余全部**：找客户 · 抓官网 · 打分 · 写信 · 排队 · 发信 · 收回复 · 分类 · 跟进 · 熔断 · 压制名单 |

推论（这条决定了页面长什么样）：**Joe 不是操作员，是决策者。**
界面要回答的是"要不要我出手"，不是"机器现在在干什么"。

---

## 2. 四页架构

| 页 | 唯一职责 | 不该出现的东西 |
|---|---|---|
| **今天** | 回答三句话：机器干了什么 · 谁在等你 · 要不要出手。**回信列表内嵌**（待处理置顶标红）+ 待拍板区 | 任何工程术语；任何"看一眼就知道、但不需要动作"的数字 |
| **客户** | 一份可筛的客户列表 + 一个「补货」按钮 | 大而全的漏斗仪表；找客户的参数配置（那是方向盘，归设置） |
| **设置** | Joe 会改的三组：**你是谁** / **机器开关** / **方向盘**（画像+词+国，折叠） | 机器算式（产能/爬坡/熔断样本）；任何他不会改的只读数字 |
| **机器房** | 回答"机器为什么这么干"。**每块以它能回答的问题作标题** | 仪表阵列（一堆数字堆在一起而不说明它回答什么问题） |

**数据看板：整页删除，内容不搬。**
理由（Joe 原话）：嫌它乱糟糟。
⚠️ **重新引入的判据（写死在这里，不靠记性）**：**累计真实发信 ≥50 封之后**，用那时的真数据重新设计一版；
在此之前不要因为"数据好像有点用"就把仪表塞回任何一页。

回复箱：并入「今天」。找客户页拆解：**补货动作 → 客户页按钮**，**方向盘 → 设置页**。

## 3. 四条铁律

### 铁律一：解释文字收进 (?) 或折叠，页面只留 **标签 + 当前值**
这仓有大量"伤疤笔记"（某个数字为什么是这个数、当年出过什么事）。
**那些属于文档和代码注释，不属于 Joe 的屏幕。**
⇒ 需要解释的，收进 `(?)` 悬浮或折叠块；页面正文只留"这是什么 + 现在是多少"。

### 铁律二：**每页字数预算做成机器判据**（错了自己会红）
沿用 C2-D 那条已被验证有效的做法（禁词表第一次跑就抓住了我自己写的文案）。

**⚠️ 判据口径（冻结，不许各量各的）：**
- **在零数据态下测量**（`leads=0`、`replies=0`）—— 页面有数据时字数当然会涨，
  预算管的是**页面自己说的话**（chrome），不是客户名字。
- 取 `#v-page`（或该页根容器）的 **`innerText` 字符数**，`\s+` 归一为单空格后计。
- 折叠块**收起时**的内容不计（它本来就不占 Joe 的视线）；`(?)` 提示内容不计。

| 页 | 空态字数上限 | 备注 |
|---|---|---|
| 今天 | **400** | 当前实测 285（C2-D 改版后），留余量给回信区与待拍板区 |
| 客户 | **500** | 列表表头 + 补货按钮 + 空态提示 |
| 设置 | **900** | 三组标签 + 控件说明（解释按铁律一折叠） |
| 机器房 | 不设上限 | 但每块**必须**以问题作标题（见铁律四的检查） |

⚠️ **测量在哪跑**：日常在本地 dev（零数据态）量，**报数时注明"本地渲染"**。
但**终验必须在生产上抽一页复量** —— 本地与生产是同一份构建产物，
可"同一份产物"是个**假设**，而假设不该免检（这仓已经栽过"生产落后 master"和"BOM 只在生产存在"两次）。

**禁词表**（Joe 视线区三页适用，机器房豁免）：
`熔断 · 爬坡 · 子请求 · 轮转 · 组合 · 阈值 · 翻牌堆 · Serper · 窗口 · 算式 · subreq`
—— 出现即判失败。

### 铁律三：**每句状态由真实配置/数据派生**，禁止写死
已经栽过三次：「免费目录刷新 ●开」（其实已撤）、「还没配 webhook」（其实配了，值脏）、
「未配置·用默认 100」（自相矛盾）。
⇒ 任何"已开启/已配置/共 N 国"之类的话，必须来自当次请求拿到的真值；
**拿不到就说"读不到"，不许显示一个看起来正常的默认值。**

### 铁律四：**每个数字，要么帮 Joe 做决定，要么不出现**
自检问句：*"这个数变了，他会做不同的事吗？"* 答不出来 ⇒ 删掉或收进机器房。
机器房的每一块也照此检查，只是那里的"决定"是排查决定 ⇒ 所以要求它**以问题作标题**
（"今天为什么没发信？"而不是"发信指标"）。

### 铁律五：**同一个事实只准有一个展示位**
别处需要提到它 ⇒ **链接过去，不许复制**。

依据（都是现存实况，不是设想）：Serper 用量住在 **3 处**、发信上限与熔断状态住在 **2 处**、
后台搜索开关状态住在 **3 处**。重复不是"多说一遍"，它是**下一次界面说谎的温床** ——
三处里改了两处，剩下那处就开始骗人，而且**没有任何东西会报错**。

⇒ 这条要在**构造上**让重叠犯不了，而不是靠每次评审去抓：
一个事实来自一个端点字段，一个字段渲染在一个位置；其它位置放跳转。

### 铁律六：**未点火 ≠ 故障，覆盖面要有清单**
C2-C 立了规则，但 `POST /api/replies/:id/draft` 当时漏网 —— 直到 C5-1 把回信详情搬进「今天」页
才暴露（它会在 Joe 主页面上每天摆一条治不好的红字）。
⇒ **每页交付时，把该页用到的端点逐个过一遍**："这个端点在能力未点火时，返回的是故障还是未点火？"
不单开一单，但每页的完成声明里必须包含这一句核对。

## 4. 附录 A：逐块搬迁施工图（找客户页解散）

| 现在住在哪 | 搬到哪 | 为什么 |
|---|---|---|
| 找客户页：画像 + 关键词 + 国家 + 预算 | **设置页 · 方向盘**（折叠） | 那是"调方向"，一年动几次，不该占日常动线 |
| 找客户页：「开始找客户」+「导入 CSV」 | **客户页 ·「补货」按钮** | 那是**动作**，动作该长在它产出结果的那一页 |
| 找客户页：「进货机器状态」块 | **机器房**（与预算/班次合并成一块） | 机器怎么想的 ≠ 我今天要干什么 |
| 找客户页：「全量重扫」 | **机器房末尾** | 少用、重、且需要先读懂代价 |
| 设置页：产能算式 / 熔断监控 / 爬坡明细 | **机器房** | 同上；设置页只留 Joe 会改的旋钮 |
| **官网询盘**（INBOUND 点火后） | **「今天」页置顶** | **比冷回信更热** —— 是对方主动找上门，最不能晾着 |

⇒ 全部搬完之后，**找客户页解散**（不保留空壳，也不留导航项）。

## 附录 B：Joe 的原始四条抱怨 → 对应的设计决定

留档以便回溯：将来有人想改架构，先看看会不会把这四条中的哪一条改回来。

| Joe 说的 | 对应决定 |
|---|---|
| 「排版乱」 | 铁律一（解释收折叠）+ 铁律二（字数预算成为机器判据） |
| 「设置页不清晰」 | 设置页只留三组（你是谁/开关/方向盘）；魔法值全部改明控件；机器算式移出 |
| 「找客户页臃肿」 | 该页拆解：动作→客户页「补货」按钮，参数→设置页方向盘 |
| 「机器房不知道干嘛」 | 机器房页首写明契约：「你通常不用来。来这的三个时刻是……」；每块以问题作标题 |

## 5. 明确不做（含重新考虑的触发条件）

| 不做 | 为什么 | 重新考虑的触发 |
|---|---|---|
| 恢复数据看板 | Joe：乱糟糟；且现在**没有真实数据**可看 | 累计真实发信 ≥50 封 |
| 把仪表塞进机器房凑数 | 机器房是"回答问题"，不是仪表的收容所 | 永不 |
| 在 Joe 视线区解释机制 | 那是文档的活 | 永不 |
| 为"信息完整"增加页面元素 | 完整不是目标，**10 分钟看完**才是 | 永不 |
| **把温室/农业设施纳入客户画像** | Joe 2026-08-31 裁定：这一类先不做 | Joe 改主意时：往画像里加这一类 + 重新分析存量线索即可（不需要改代码） |
