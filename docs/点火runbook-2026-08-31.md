## §0 先解决一件会让你以为"没权限"的事（每次开工都要）

这台机器上有**两套 Cloudflare 凭据**：
- 环境变量 `CLOUDFLARE_API_TOKEN`（User 级、只读，供跨窗验证用）
- 本机 OAuth 登录（`wrangler login` 存的，有完整写权限）

⚠️ **wrangler 一见环境变量就优先用它、无视 OAuth**。症状是 deploy 报
`Unable to get membership roles ... missing User->Memberships->Read`、D1 报 `7403 / 10000` ——
看起来像"权限被撤了"，其实是**被抢道**。

**所有写操作（deploy / D1 / secret put）都在摘掉变量的进程里跑：**
```powershell
$env:CLOUDFLARE_API_TOKEN=$null; npx wrangler <命令>
```
自查（应显示 OAuth 与 zq8345@gmail.com）：
```powershell
$env:CLOUDFLARE_API_TOKEN=$null; npx wrangler whoami
```

## §3 试发：三重防护（上游真误发过 2 封，这一节是拿事故换来的）

上游的错法是：以为 `x.com` 是个不存在的域 → 真发出去 2 封。**"我以为它不存在"不是判据。**

### ① 先证进程身份（永远第一步）
```powershell
curl.exe -s http://127.0.0.1:8791/api/_whoami     # 本地
```
必须看到 `"repo":"airsonde-crm"`。这台机器上同时跑着别的窗的 worker，**端口通 ≠ 打到了我的进程**
（实测栽过：8788 上答话的是 airsonde-admin）。

### ② 目标只用 Resend 官方模拟地址（**不猜"应该没人用"的域名**）
| 地址 | 用途 |
|---|---|
| `delivered@resend.dev` | 模拟送达 |
| `bounced@resend.dev` | 模拟硬退信（验 webhook 是否自动压制） |
| `complained@resend.dev` | 模拟投诉（验自动拉黑） |
| `suppressed@resend.dev` | 模拟命中压制名单 |
（`delivered+xxx@resend.dev` 可加标签区分多次测试。2026-08-31 查 Resend 官方文档核实。）

**这些地址不会到达任何真人**，比任何"我觉得没人用的域名"都可靠。

### ③ 真实测试邮箱（Joe 自己的信箱）先进压制名单
真要往自己邮箱发之前，先把它写进压制名单，**验证"闸真的拦得住"**，再决定是否放开。

**推荐走后台**（这是产品里已有的路，不用碰数据库）：
新建/找到一条用该邮箱的线索 → 把状态改成**黑名单**或**退订** → 系统自动把这个邮箱写进压制名单
（`addSuppressedEmail`，单条与批量两条路径都会触发）。
然后再点「发送」，**应该被拦住**并提示压制 —— 拦住了才说明闸是活的。

需要脱离线索直接写（例如给一个还没建线索的地址）时才走 D1：
```powershell
$env:CLOUDFLARE_API_TOKEN=$null
npx wrangler d1 execute airsonde_crm --remote -y --command "INSERT OR IGNORE INTO suppressed_emails (email, reason) VALUES ('joe@example.com','ignition-test')"
```
⚠️ 移出压制名单没有后台入口（合规上本来就不该轻易移），要移只能走 D1 `DELETE`。

### 试发怎么走
- **自动发送保持关闭**（后台设置页）。⛔ 钥匙到位不等于放开自动发。
- 只用**手动单条发送**（后台线索详情页的「确认发送」）。
- 前置条件（`sendLead` 的真实闸，别绕）：线索有邮箱 · 已打分 · 未压制；没草稿会当场用 AI 现写一封。

## §4b 配好 `LARK_IMAP_PASS` 后：第一封真实回复必须核分类（C6-B/P0-1 的集成验证）

C6-B 把 `classify()` 接到了统一 `chat()`（额度 200 → `TOK_CLASSIFY=2000`），并让三条
**原本静默落成 `"other"`** 的失败路径（`!res.ok` / 空内容 / 异常）变得可辨识。
但**这条链在 IMAP 点火前生产不可达**，所以改动至今没有被真实流量验证过。

⇒ 第一封真实回复进来时，核这一条：

- **分类结果不是 `other`** —— 或者是 `other` 但**带 `error`**（那说明是"没分成"，不是"这封真是其他"）
- ⚠️ **若一批全是 `other` 且一个 `error` 都没有** —— 先怀疑 `TOK_CLASSIFY` 还是不够
  （`replies.ts` 里改，别在别处另加兜底）

判据在返回值里：`IngestResult.results[].classifyError`。**"全 other" 与 "全失败" 现在分得开** ——
这正是这次改动要买的东西，别在第一封信上就放过它。

## §6 ⛔ 发信前的硬闸：公开退订入口（C2-F，尚未做）

现在 `crm.airsonde.com` **整站在 Access 门后**、`workers_dev:false`、`API_HOST` 未配 ⇒
**退订链接、Resend webhook 都不可达**。

后果分两条，**都不能接受**：
- 收件人点退订 → 打到 Access 登录页 → **等于没有退订入口**（合规违规）
- Resend 的退信/投诉 webhook 进不来 → **熔断器与自动压制名单全瞎**（发得越多越危险）

⇒ **C2-F 落地前，一封信都不许发。** 方案（api.airsonde.com 公开正门 vs 独立轻 worker）见
`docs/发信通道选型-2026-08-12.md` §3 与 `docs/官网询盘接入契约-2026-08-12.md` §5，本单不开。

## §6b ⛔ 开 Access 验签强制前：必须先配 `ACCESS_AUD`（C6-B/P2-5）

`src/accessjwt.ts` 里的 `DEFAULT_ACCESS_AUD` 是
`9a9ae044d1db07e6ce75992743d4698fedc9b246898b2c0ad4f39e20dcf7ef97` —— **那是 wanew-crm 应用的 AUD**，
不是 AirSonde 的（AirSonde 是 `b7c3296b…`）。fork 时随代码一起搬过来的。

**今天无害**：这段只观察不拦截，AUD 对不上也不会拒绝任何人。
**但开强制的那一刻它会变成致命项**——两种结果都很坏，取决于比对方向：要么把所有人挡在门外，
要么拿另一个应用的 AUD 当通过条件。

⇒ 开强制**之前**必须先执行（值由 Joe 亲手配，不经过任何窗口）：

```bash
wrangler secret put ACCESS_AUD
```

⚠️ **不要靠改那个默认常量来解决**：常量是"没配时的兜底"，而这类值就不该有兜底 ——
一个写死的、看起来合理的 AUD 正是最容易被误当成"已经配好了"的东西。
配了 `ACCESS_AUD` 后 `env.ACCESS_AUD` 优先（`accessjwt.ts:175`），常量自然不再参与。

⚠️ 判断"装没装上"只认三信号：**302 + `Www-Authenticate` + `CF_AppSession`**。
Cloudflare Access 的 `GET /access/apps` 在无 Zero Trust 权限时会返回 `success:true` + **空列表**，
与"真的一个应用都没有"完全同形 —— 别拿它当证据。

## §7 出事了怎么急停

| 情况 | 动作 |
|---|---|
| 想立刻停掉所有自动发信 | 后台设置页关「自动发送」；它**不会自己恢复** |
| 想连机器一起停 | `wrangler.jsonc` 去掉 `triggers.crons` → `npm run deploy` |
| 要彻底断发信能力 | `npx wrangler secret delete RESEND_API_KEY` → 立即回到 fail-closed（发信路径第一行就拦） |
| 退订率异常 | 熔断器在最近 30 封自动信里退订 ≥15% 时自动停；手动重开在设置页 |
